Each locale contains title.txt, short_description.txt (at most 80 characters),
full_description.txt (at most 4000 characters), changelogs/<versionCode>.txt,
images/icon.png (512x512 RGBA), images/featureGraphic.png (1024x500 RGB),
images/phoneScreenshots/ (six portrait 1440x2560 and two landscape 2560x1440 RGB PNGs), and screenshot alt texts.
The structure can be used by fastlane supply and F-Droid's metadata importer.
The optional alt-text JSON is a copy/paste aid for Play Console, not an uploader.

Screenshots show the actual app UI on Pixel_8_API_36, Android 16. The selected
stock package was downloaded and verified in the emulator. No USB flashing was
performed. Firmware bytes are not included in this material pack. The example
firmware illustration is generated by the app, not a manufacturer product photo.

Raw 1080x2400 / 2400x1080 captures are in screenshots/raw/<locale>/. Store copies remove
only the Android status/navigation bars and are centered without distortion on
a 9:16 or 16:9 canvas. No app controls, data or update outcomes were fabricated.
01: catalog/search, light; 02: favorites, light; 03: downloads offline, light;
04: package details, dark; 05: Flasher downloaded-package selection and install action, dark;
06: language selection, dark.
07: landscape catalog with a filter sidebar; 08: landscape two-column Flasher.

Graphics use the existing app waveform and original vector shapes. The editable
icon is ../assets/icon.svg. Recreate the PNGs and frame raw screenshots with:
python3 publication/build_graphics.py
This helper requires Pillow and DejaVu Sans / Noto Sans CJK fonts.

BUILDS
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:bundleRelease
Test APK: app/build/outputs/apk/debug/app-debug.apk (debug signed).
Release bundle: app/build/outputs/bundle/release/app-release.aab (unsigned unless
the ANDROID_KEYSTORE_* / ANDROID_KEY_* environment variables are configured).
Use Android Studio's Generate Signed Bundle / APK workflow with your private
upload key before uploading to Google Play, and enable Play App Signing there.
Alternatively, use the GitHub Actions signing and publishing pipeline described
in github-actions.txt. It can build a signed bundle for the first manual upload,
publish subsequent versions to internal testing, and promote a tested version
to production without uploading the same versionCode twice.
Keep the keystore, passwords and service-account keys outside Git. The unsigned
bundle and debug APK have different publishing purposes; only a correctly
signed release bundle should be sent to Play Console.

GITHUB / F-DROID
Source: https://github.com/ekim-pl/android-fm1-flasher
Releases: https://github.com/ekim-pl/android-fm1-flasher/releases
github-release.txt contains the test APK release notes. The APK is debug signed;
its SHA-256 checksum and a manual test checklist accompany the prerelease.
fdroid/pl.ekim.fm1_flasher.yml is a draft build recipe with the public source
and release tag filled in. Validate it with fdroidserver before submitting
an inclusion request. Catalog and downloaded stock-firmware licensing
must be described to the reviewer; acceptance is decided by F-Droid.

PLAY CONSOLE
play-console.json contains factual listing/account declarations to enter.

if requested by the Play Console foreground-service declaration.

REMAINING ACCOUNT / HARDWARE STEPS
1. Verify the complete update flow on a physical phone and FM-1. This release is
   still experimental and the store descriptions state that explicitly.
2. Enter the public source and privacy-policy URLs from play-console.json in
   Play Console. The F-Droid recipe is not an accepted listing or an APK repository.
3. Sign the release bundle with your upload key; complete Play account verification,
   content rating, target audience, data safety and foreground-service forms.
4. Review external catalog/image/firmware server data practices before finalizing
   Data safety. Request URLs, IP addresses and generic User-Agent reach those
   servers even though the app has no publisher telemetry backend.
5. Complete applicable closed testing and store reviews. The GitHub prerelease
   is for testing; no Google Play upload or F-Droid submission has been performed.
