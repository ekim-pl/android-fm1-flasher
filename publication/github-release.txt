FM-1 Flasher 0.8.1 — localized source guides and Awesome FM-1

## Changes
- Expands the in-app About page in English, Polish and Simplified Chinese with instructions for adding, configuring, enabling and removing firmware sources, checking status, filtering by source and restoring defaults.
- Explains refresh limits, optional background checks, offline use and preservation of downloaded packages and favorites.
- Adds a dedicated **Awesome FM-1** project section: its role as a companion community firmware directory, how to enable the built-in source, publisher-hosted downloads and how to contribute projects or report outdated entries.
- Updates the same localized content on the project website and links the companion catalog from the main README.
- Includes the multi-source SQLite library from 0.8.0-experimental. **The Firmware Hub remains enabled by default; Awesome FM-1 remains disabled by default.** Existing source settings and local packages are preserved on update.
- Uses version name **0.8.1**, version code **15** and application ID `pl.ekim.fm1_flasher`. Requires Android 14+.

## Validation
- 110 JVM tests passed without skips using a saved Hub catalog and hash-verified V15 and SHRUB packages. V16 was not included.
- 23 instrumentation tests passed on Android 16, including SQLite migration, source settings and background-work guards. API 34 and API 36 also have platform jobs in Android CI.
- Installation over the existing app preserved all source records and request limits, catalog entries, downloaded packages, favorites and application settings. The signing certificate matches 0.8.0-experimental.
- Debug and unsigned release APK/AAB builds and both lint variants passed. The release fixture gate, its two helper tests and checks for 44 generated documentation pages passed. All three updated About documents are bundled in the APK; their localized rendering was checked on the emulator during preparation of this update.

## Installation
Install `FM1-Flasher-0.8.1-debug.apk`. This GitHub release follows the existing debug-signed APK distribution and updates 0.8.0-experimental with the same signing certificate. Data from the separate `.experimental` and `.recovery` application IDs is not migrated. No firmware package is bundled in the APK.

Open **Settings → Firmware sources** to manage catalogs. Enable **Awesome FM-1** there to use its additional catalog. Background catalog checks and **Settings → Experimental features** remain optional and off by default on a new installation.

## Known limits
The GitHub release channel does not change the existing hardware restrictions. SHRUB still has unknown flash-chip compatibility and remains blocked from flashing. Physical SHRUB flashing, USB ROM recovery, both-chip hardware acceptance and sustained multi-port load testing remain unverified. Catalogs currently have no verified publisher signature; awesome-fm1 publisher automation and catalog signing remain separate work. Existing toolchain dependency advisories are documented in `docs/reviews/0.7.0-validation.md` and its audit.
