GitHub Actions on main — 0.9.2

This is a description of the checked-in workflows, not a request to run or publish them.
Android application ID: pl.ekim.multiplatform_fm1_flasher.
Stable 0.9.2 uses the v0.9.2 GitHub tag; Google Play publication is separate.

ANDROID CI (.github/workflows/android-ci.yml)
Runs on branch pushes, pull requests and manual dispatch. Uses JDK 17, Android SDK 36
and Build Tools 35.0.0. Checks generated resource bridges, shared JVM tests, Android
JVM tests, debug lint and assembleDebug. Uploads APK/reports as android-checks for
14 days. The platform matrix separately runs explicit instrumentation classes on Android API 34 and 36.
It does not run a physical FM-1, create a GitHub Release or build Swift.

PAGES (.github/workflows/pages.yml)
Builds documentation and checks links on every branch/PR or manual dispatch.
Non-PR default-branch runs deploy to Pages. Manual dispatch on task/multiplatform-rework may also deploy.
A push to task/multiplatform-rework normally validates the site without deploying it.
The current branch's documentation can differ from the public default-branch site.
See website/pages.md for local commands and output layout.

GOOGLE PLAY RELEASE (.github/workflows/google-play.yml) — ORIGINAL-APP CONFIGURATION
Triggered by manual dispatch only. The manual publish input defaults
true. The workflow builds a signed AAB and can upload it to the internal track.
However, its fastlane --package_name is still pl.ekim.fm1_flasher, while this branch's
AAB has pl.ekim.multiplatform_fm1_flasher. This is not a configured publishing route
for the fork. Tags do not start the Play workflow. No automatic GitHub Release creation is defined.

The Gradle FM1_RELEASE_TAG guard expects v<versionName> when that variable is set.
A future GitHub prerelease needs a deliberately chosen tag/commit and manually or
separately uploaded, verified assets. Choosing a tag is not sufficient to adapt Play.
Keep test handoff, owner/hardware acceptance and publication as separate steps.

GOOGLE PLAY PRODUCTION (.github/workflows/promote-production.yml)
Manual dispatch accepts a positive version_code and promotes an internal-track
bundle to production. It also targets the original pl.ekim.fm1_flasher package.
It does not build a new bundle and is not a promotion route for this fork.

SIGNING CONFIGURATION (CODE FACTS)
Local Gradle release signing reads ANDROID_KEYSTORE_FILE, ANDROID_KEYSTORE_PASSWORD,
ANDROID_KEY_ALIAS and ANDROID_KEY_PASSWORD. Without the key configuration a local
bundleRelease is unsigned. Keep all keys/passwords outside Git.
The inherited release workflow uses the google-play environment and
ANDROID_KEYSTORE_BASE64 plus the password/alias secrets; publication also uses
GOOGLE_PLAY_SERVICE_ACCOUNT_JSON. The production workflow uses google-play-production
and that service-account secret. These facts do not establish account access,
package registration, signing continuity or readiness for a store release.

BEFORE ADAPTING STORE PUBLICATION
Resolve the intended application ID, store entry, upload certificate and versionCode;
review both workflow package_name values, the original-app F-Droid recipe, listing
assets and current privacy/data inventory. Existing screenshots are from earlier UI.
Complete physical hardware acceptance and the owner's test-build review first.
This documentation regeneration does not alter workflows, secrets or store settings.
