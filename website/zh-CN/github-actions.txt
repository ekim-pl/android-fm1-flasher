GitHub Actions：FM-1 Flasher

本文描述仓库中的工作流，不会执行发布。
Android ID：pl.ekim.fm1_flasher。0.9.1 APK 仅为本地测试构建。

ANDROID CI (.github/workflows/android-ci.yml)
分支推送、PR 或手动触发。使用 JDK 17、SDK 36、Build Tools 35.0.0。
检查生成资源、shared JVM 与 Android JVM 测试、debug lint 和 assembleDebug。
android-checks 保存 APK/报告 14 天。不测试真实 FM-1，不创建 GitHub Release，
不构建 Swift，也不执行独立的 Android 仪器化验收测试。

PAGES (.github/workflows/pages.yml)
在所有分支/PR 或手动运行时构建文档并检查链接。
只有默认分支上的非 PR 运行（包括手动运行）会部署。其他分支只构建并验证网站。
当前分支文档可能与公共网站不同。本地命令与输出结构见 Pages 指南。

GOOGLE PLAY RELEASE (.github/workflows/google-play.yml)：原应用配置
仅手动 dispatch 会触发，手动 publish 默认 true。
它构建签名 AAB 并可能上传 internal，包名为 pl.ekim.fm1_flasher。发布前需验证签名和商店配置。
标签不会触发 Play 工作流。
现有工作流没有自动创建 GitHub Releases 的步骤。

设置 FM1_RELEASE_TAG 时，Gradle 要求 v<versionName>。未来 GitHub 预发布需明确选择
标签/提交，再单独上传已验证资产。标签本身不会修正 Play 配置。
测试文件交付、所有者/硬件验收与发布应分别执行。

GOOGLE PLAY PRODUCTION (.github/workflows/promote-production.yml)
手动输入正整数 version_code，将 internal 现有 bundle 提升到 production。
它指向 pl.ekim.fm1_flasher，不构建新包。

签名配置事实
本地 Gradle 读取 ANDROID_KEYSTORE_FILE、ANDROID_KEYSTORE_PASSWORD、ANDROID_KEY_ALIAS、
ANDROID_KEY_PASSWORD。无密钥配置时 bundleRelease 不签名。密钥和密码不要加入 Git。
继承的 release 工作流使用 google-play 环境、ANDROID_KEYSTORE_BASE64 和密码/alias secrets；
发布还使用 GOOGLE_PLAY_SERVICE_ACCOUNT_JSON。Production 使用 google-play-production 和服务账户密钥。
这些配置不证明账户权限、包注册、签名连续性或商店发布准备完成。

适配商店发布前
确定应用 ID、商店条目、上传证书和 versionCode。复核两处 package_name、原应用 F-Droid
归档配方、描述/截图及当前隐私数据清单。已有截图展示旧界面。
先完成硬件验收与所有者测试 APK 确认。本次文档更新不修改工作流、secrets 或商店设置。
