# Privacy Policy — FM‑1 Flasher

FM-1 Flasher 0.10.0: source colors and interface preferences are stored only on this device. The Google Play distribution includes Google Analytics for Firebase; usage statistics are enabled by default and can be disabled in Settings. The F-Droid distribution contains no Firebase or analytics SDK.

## Publisher and contact

ekim.pl@gmail.com. Effective date: November 15, 2026. This policy describes how FM-1 Flasher processes data.

## Local information

The app requires no account and contains no advertising. Standard builds contain no analytics SDK. Builds configured with Google Analytics for Firebase collect usage statistics by default from the first online launch. You can turn statistics off at any time in Settings → Usage statistics. Optional private catalog sources may require their own credentials or OAuth account. Favorites, browsing preferences, theme and language choices, cached catalogs, preview images, firmware packages and download metadata are stored in private app storage. A bounded operation log (up to 256 KiB) is saved in private app storage and survives restarts. It records timestamps, operations, USB/MIDI port events, transfer stages and error messages; it does not record raw MIDI traffic or firmware contents. URL query strings and fragments are removed from logged messages. In experimental settings you can export it as JSON Lines or clear it. Logs are never uploaded automatically. Exported files remain at the destination you choose and may contain device names, USB paths and technical error details; review them before sharing. Instrument names, observed USB serials, memory-type selections, last known firmware identity and task history (targets, package hashes, stages and results) are stored locally. Serial numbers are not included in the ordinary connection log. The most recently removed valid package can be restored while the app session remains open. These data are not uploaded to the app publisher. Source provider selection, public authentication configuration, Basic usernames, OAuth client IDs/scopes and package compatibility declarations are stored locally. Passwords, API keys, OAuth access/refresh tokens, client secrets and pending PKCE verifiers are encrypted with an Android Keystore key in private storage, separate from catalog metadata. Authentication input fields are not written to the operation log or activity saved state. Headers are restricted to the configured resource origin and removed on cross-origin redirects; token POST redirects are refused. Optional OAuth sign-in opens the browser and communicates with the configured authorization/token servers, whose operators process authentication under their own policies. No instrument identity or settings are attached to those requests. Removing a source or restoring its built-in defaults removes its saved secrets; uninstalling/clearing app data removes application-held credentials. Local non-secret source history/provenance can remain after subscription removal.

## Network connections

When online, the app checks enabled catalog sources and may fetch their permitted preview images. The Firmware Hub is enabled by default; awesome-fm1 on raw.githubusercontent.com and custom sources require opt-in. Disabled sources make no automatic requests; Check now is an explicit one-time request even for a disabled source. Enabled source checks contact GitHub or approved publishers. Repository/package-URL checks may fetch firmware headers or complete FWSC bytes to identify and hash packages, including optional background checks when enabled. Choosing Download explicitly stores a verified offline library copy. Regular checks follow a per-source 24–168 hour schedule, including failed attempts. Explicit credential replacement or successful OAuth authorization permits a new check. Optional background catalog checks use WorkManager and are off by default; offline mode pauses them. All requests use HTTPS. No firmware is installed automatically.

## Information visible to external services

Operators of those servers receive the requested URL, the connection IP address and standard HTTPS connection metadata. The app sends a generic technical User-Agent that does not identify an individual user or device. Apart from authentication explicitly configured for a source, the app does not attach favorites, settings, instrument memory contents, MIDI identity or an account identifier to these requests. Server operators handle technical logs under their own privacy policies; the app publisher does not control their retention or processing.

## USB MIDI

The app reads the identity of the FM-1 explicitly selected by the user and transfers a selected firmware package over USB MIDI after the user confirms an update. USB device details and MIDI responses are used to manage that local session and are not sent to network services or the app publisher.

## Storage, deletion and offline use

Local data remain on your device until removed in the app, cleared in Android app settings, or deleted by uninstalling the app. Removing a package leaves favorites intact. Catalogs, source policies and local-package metadata use SQLite. Removing a subscription retains provenance, known withdrawals, packages and favorites. Clearing app storage or uninstalling removes the library and preferences. Android app data backup is disabled. There is no application account. Analytics data, where enabled, are processed separately as described below. In offline mode, the app does not refresh the catalog or download packages or preview images; previously saved content remains available.

## Changes and questions

Updated policies will be included with relevant app updates and in the project repository. For privacy questions, contact ekim.pl@gmail.com.


Usage statistics in Firebase-enabled builds are on by default from the first online launch. To stop collection, turn off Share usage statistics in Settings → Usage statistics; the choice is stored locally and preserved across restarts and updates. This default is an application preference, not a record of explicit user consent. Google processes screen names, operation results/categories and timings, app-instance identifiers, app/OS/device information and network metadata, including approximate location derived from IP. These data are pseudonymous, not anonymous. We do not attach instrument identity, serials, names, private source URLs, credentials, firmware contents or logs. Advertising storage, advertising identifiers and advertising personalization are disabled. Offline mode pauses collection and requests a local SDK reset; an upload already in progress may finish. Turning statistics off stops new collection and resets local analytics data; it does not delete data already sent to Google. Events and operations from a disabled period are discarded, not uploaded later. Re-enabling resumes collection of new events. User/event-data retention depends on the GA4 project configuration; aggregated reports may be retained longer. Google processes data under its privacy policy (https://policies.google.com/privacy). Contact the publisher for privacy requests and retention details.
