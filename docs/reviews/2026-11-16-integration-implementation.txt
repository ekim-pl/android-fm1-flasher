CHANGES
- AppSnapshot exposes nullable historyRetentionMillis (default 30 days).
  AppAction supports HISTORY_RETENTION/HISTORY_CLEAR. Android Activity observes
  the service policy and dispatches validated 7/30/90/unlimited settings and
  clear requests through existing asynchronous, busy-gated service APIs.
- Settings shows history only for fleet-capable Android, independently of
  experimental logging. Clear requires the shared FlasherApp confirmation;
  confirmation and settings mutations are disabled while busy. Copy explicitly
  protects queued/running jobs, backups and unresolved recovery records.
  English/Polish/Simplified Chinese XML and generated resources synchronized.
- Portable backend explicitly rejects these unsupported actions using the
  existing platform-limits status. Existing log controls remain intact.
- Verified OAuth defect: libraryTask can finish before OAuthManager consumes
  state (offline/network unavailable), leaving dispatchedState permanently set.
  Service now calls a completion hook even for rejected handoff. Activity uses
  it to terminate that attempt: remove the matching unconsumed PKCE request and
  encrypted callback, release its process claim, and request a fresh login.
  A newer login is not invalidated by an older completion. Successful exchange
  still consumes state before requesting tokens. No automatic retry loop or
  second token exchange; cold-process recovery before completion still exists.
  This intentionally chooses fresh authorization after a failed handoff rather
  than replaying a potentially ambiguous asynchronous authorization attempt.
- Corrected an existing PortableAppBackendTest assertion: non-localized
  IllegalArgumentException produces AppText.Plain through appMessage(), not the
  fallback library_change_error resource. The old assertion timed out. The test
  now waits for the error report and verifies the policy stays at 14 days and
  survives reconstruction. No production logging behavior changed for this fix.
